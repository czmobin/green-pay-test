# فرانت‌اند گرین‌پی

Next.js 14 با App Router، TypeScript، بدون کتابخانهٔ UI. کل رابط فارسی و راست‌به‌چپ
است و تقویمش شمسی.

راه‌اندازی محلی در [README ریشه](../README.md). این فایل دربارهٔ ساختار و قراردادهای
داخلی است.

---

## شکل کلی

یک `StoreProvider` در `components/store.tsx` بالای همه‌چیز نشسته و تنها منبع داده
است. هیچ صفحه‌ای مستقیم `fetch` نمی‌زند؛ همه از `useStore()` می‌خوانند.

جریان داده ساده است: هنگام بالا آمدن اپ یک `GET /api/bootstrap/` می‌رود و همهٔ داده
را می‌آورد. بعد از آن هر تغییری یک درخواست نوشتن می‌فرستد و پاسخش را روی state
می‌نشاند. هیچ کش لایه‌ای و هیچ کتابخانهٔ state management‌ای در کار نیست —
`useState` و `useMemo` برای این اندازه کافی بودند.

`store.tsx` حدود ۷۰۰ خط است و بزرگ‌ترین فایل پروژه. اگر جایی گم شدید، از آنجا شروع
کنید: هر چیزی که رابط نشان می‌دهد از یکی از مقادیر همین فایل می‌آید.

## قراردادها

**استایل‌ها همه در `globals.css`اند** و از توکن‌های CSS استفاده می‌کنند
(`--brand`، `--panel`، `--ink`، `--line`…). نه Tailwind هست، نه CSS Module، نه
styled-components. تم روشن/تیره با `data-theme` روی `<html>` عوض می‌شود و یک اسکریپت
کوچک در `layout.tsx` پیش از رندر اولش را از `localStorage` می‌خواند تا صفحه با تم
اشتباه فلش نزند.

**تاریخ‌ها همه‌جا شمسی‌اند** و تبدیلشان در `lib/jalali.ts` است — حدود ۹۵ خط، بدون
وابستگی بیرونی. یک پیادهٔ دوم از همین منطق در پایتون هست
(`backend/meetings/jalali.py`) که برای متن پیامک و گزارش به‌کار می‌رود.

**ساعت‌ها اعشاری‌اند.** `14.5` یعنی ۱۴:۳۰. این قالبی است که API می‌دهد و تقویم
مستقیم با آن کار می‌کند.

**فونت Vazirmatn با `next/font/google`** گرفته می‌شود. یعنی **هنگام build** به
اینترنت نیاز است؛ بعد از آن فونت داخل خروجی میزبانی می‌شود و در زمان اجرا هیچ
وابستگی به CDN نیست.

**`NEXT_PUBLIC_API_URL` موقع build باندل می‌شود.** در production خالی می‌ماند و
مقدار پیش‌فرض `/api` جواب می‌دهد، چون nginx هر دو را زیر یک دامنه آورده.

## دامنهٔ نمایش (Scope)

نوار بالای صفحه بین این حالت‌ها جابه‌جا می‌شود: `mine`، `ceo`، `shared`، `all`.
هر تب شرط خودش را دارد و بی‌دلیل نشان داده نمی‌شود:

- «مدیرعامل» فقط برای ادمین، و فقط وقتی مدیرعاملی تعریف شده باشد.
- «همه» فقط برای نقش‌های مدیریتی.
- «تقویم‌های اشتراکی» فقط وقتی کسی تقویمش را با این کاربر به اشتراک گذاشته.

`canEdit` و `canWriteMinutes` در store، تکرار سمت‌کلاینتِ همان قواعد بک‌اند هستند.
این تکرار عمدی است و فقط برای این است که رابط از پیش دکمهٔ غیرفعال نشان بدهد به‌جای
اینکه کاربر کلیک کند و ۴۰۳ بگیرد. **کنترل واقعی همیشه سمت سرور است.** اگر قواعد
بک‌اند را عوض کردید، این دو را هم عوض کنید؛ وگرنه رابط دکمه‌ای نشان می‌دهد که API
ردش می‌کند.

## چاپ تقویم هفتگی

دکمهٔ «چاپ هفته» در نمای هفتگی دو صفحهٔ مستقل تولید می‌کند: یک نمای تقویمی
(شبکهٔ ساعت × روز، برگهٔ افقی) و یک نمای فهرستی. کلش با `@media print` در
`globals.css` کار می‌کند و روی صفحه دیده نمی‌شود.

دو نکته که اگر دست بزنید باید بدانید:

ارتفاع هر ردیف ساعت را CSS از بودجهٔ برگه درمی‌آورد
(`--ph: min(18mm, 150mm / --span)`)، نه JS. یعنی جا شدن شبکه در یک برگهٔ A4 افقی یک
ثابت است و با شلوغ شدن هفته نمی‌شکند. اگر این را به عدد ثابت برگردانید، هفتهٔ شلوغ
به صفحهٔ دوم می‌افتد و صفحهٔ اول فقط سرصفحه چاپ می‌شود.

ارتفاع کارت‌ها دو رفتار دارد: جلسه‌ای که با هیچ جلسهٔ دیگری هم‌پوشانی ندارد ارتفاعش
را از **مدتش** می‌گیرد (۱۴ تا ۱۶ دقیقاً دو ردیف)، ولی جلسه‌های هم‌پوشان تمام‌عرض و
پشت سر هم می‌آیند و ارتفاعشان از **محتوایشان**. دلیلش این است که وقتی کنار هم و
نصف‌عرض می‌نشستند، جلسهٔ بلند دو ردیف فضای خالی داشت و عنوان جلسهٔ کوتاهِ کنارش وسط
کلمه بریده می‌شد. منطقش در `layoutPrintDay` داخل `Calendar.tsx` است.
